# IDH 协同平台 · 视觉设计规范

> 版本: V1.0 | 日期: 2026-11 | 适用: 平台 Web 端 + 车间 H5

---

## 1. 设计定位

不是"好看就行"的偏好清单，而是一套可交付、可验收的规则。

**三个关键词：**

| 关键词 | 含义 | 落地方式 |
|--------|------|---------|
| **清爽 Airy** | 大量留白、极少的线、只保留必要信息 | 一屏只讲一件事，让眼睛知道先看哪里 |
| **锐利 Precise** | 数字对齐、字距收紧、边缘干净 | 芯片行业的气质是精密，不是圆滚滚的可爱 |
| **有节奏 Rhythmic** | 统一 8pt 间距、统一圆角阶梯、统一动效时长 | 节奏感来自"一致"，不是来自装饰 |

**三条边界（不做这些）：**

- ❌ 卡通人物插画、3D 小人、夸张表情包
- ❌ 满屏渐变、霓虹描边、发光字
- ❌ 超过 22px 的大圆角（会显得幼稚）

> 判断标准：把它给一位 35 岁的采购经理看，他觉得"专业但轻松"就对了；觉得"像游戏界面"就过头了。

## 2. 色彩系统

一个主色，两个点缀，剩下交给中性灰。主色承担 90% 的品牌识别，青与柠檬只做"呼吸感"点缀，绝不参与信息编码。

### 2.1 品牌色

| 名称 | 色值 | 用途 |
|------|------|------|
| **Brand 600** | `#4F46E5` | 主按钮、链接、选中态 |
| **Brand Gradient** | `#4F46E5 → #7C3AED` | 仅用于主按钮与重点数字 |
| **Brand Soft** | `#EEF0FF` | 浅底、标签背景、hover 行 |
| **Cyan 500** | `#06B6D4` | 图表第二色、进度、点缀 |

### 2.2 中性色（页面 90%）

| 名称 | 色值 | 用途 |
|------|------|------|
| **Ink 900** | `#0A0F1E` | 标题、深色区块底 |
| **Ink 800** | `#1B2436` | 次级标题 |
| **Body** | `#3F4B60` | 正文 |
| **Muted** | `#6B7A90` | 辅助说明、图注 |
| **Faint** | `#98A4B8` | 禁用态、占位 |
| **Line** | `#E7EBF3` | 描边、分割线 |
| **Line 2** | `#F0F3F9` | 表格分割线 |
| **Canvas** | `#F6F8FC` | 页面底色（冷灰，不用纯灰） |
| **Paper** | `#FFFFFF` | 卡片、输入框底 |

### 2.3 语义色

| 名称 | 色值 | 用途 |
|------|------|------|
| **Success** | `#10B981` | 账实相符、已关闭 |
| **Warning** | `#F59E0B` | 接近安全线、待处理 |
| **Danger** | `#EF4444` | 差异超标、超期 |
| **Info** | `#0EA5E9` | 在途、进行中 |

### 2.4 配色三条硬规则

1. 一屏内高饱和色不超过 2 处
2. 渐变最多两个色相，角度固定 135°（品质感来自一致，不来自变化）
3. 禁止纯黑 `#000` 与纯灰 `#808080`，全部用带蓝调的墨色与冷灰。正文对比度 ≥ 4.5:1，大字 ≥ 3:1

## 3. 字体与字阶

标题压紧、正文放松、数字对齐。中文优先 HarmonyOS Sans SC / PingFang SC，数字与英文用 Inter。

**字体栈:**
```css
font-family: "Inter", -apple-system, BlinkMacSystemFont,
  "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif;
```

### 3.1 字阶体系

| 层级 | 字号 | 字重 | 字距 | 行高 | 示例 |
|------|------|------|------|------|------|
| **Display** | 62px / clamp(38,5.4vw,62) | 800 | -0.035em | 1.05 | "对账，不该靠猜" |
| **H2** | 34px / clamp(26,3vw,34) | 800 | -0.025em | 1.25 | "三账对齐模型" |
| **H3** | 17px | 700 | -0.01em | — | "差异必须落到可归因的类别" |
| **Body** | 15.5px | 400 | 0 | 1.8 | 正文段落 |
| **Micro** | 11px | 700 | 0.16em 大写 | — | "RECONCILIATION · T+1" |
| **Code** | 12.5px | — | — | — | 内联代码 |

### 3.2 数字排版

所有数量、金额、比率必须开启 `font-variant-numeric: tabular-nums`，并在表格中右对齐。这是"精密感"最廉价也最有效的来源——错位的数字会立刻让系统显得业余。

## 4. 间距、栅格与形状

### 4.1 8pt 基准间距

所有间距取自 4 的倍数：

| 刻度 | 值 | 用途 |
|------|-----|------|
| 4px | `--space-4` | 图标与文字 |
| 8px | `--space-8` | 行内元素 |
| 12px | `--space-12` | 表单项 |
| 16px | `--space-16` | 卡片内边距（小） |
| 24px | `--space-24` | 卡片内边距（中） |
| 32px | `--space-32` | 卡片间距 |
| 56px | `--space-56` | 区块间距 |
| 88px | `--space-88` | 章节间距 |

### 4.2 圆角阶梯（仅五档）

```
8px  → 小元件（徽标、标签内圆角）
12px → 输入框
16px → 卡片（"现代但不幼稚"的分界线）
22px → 大容器
999px → 胶囊按钮、标签
```

超过 22px 的圆角只允许出现在胶囊按钮与标签上。卡片一律 16px。

## 5. 组件规范

能靠描边解决的，就不要加阴影。层次优先顺序：**留白 > 描边 > 底色差 > 阴影**。

### 5.1 按钮

| 变体 | 样式 | 用途 |
|------|------|------|
| **Primary** | `linear-gradient(135deg, #4F46E5, #6366F1)` + shadow | 主操作 |
| **Ghost** | 白底 + `#E7EBF3` 描边 + 深色文字 | 次要操作 |
| **Quiet** | `#EEF0FF` 底 + 品牌色文字 | 低优先级 |
| **Danger** | `#FEF2F2` 底 + 红色文字/描边 | 危险操作 |

**规格:** 高度 40px · 圆角 10px · 图标与文字间距 7px

### 5.2 状态标签 (Pill)

```
● 账实相符  — #ECFDF5 底 / #047857 字
● 待申辩    — #FFFBEB 底 / #B45309 字
● 差异超标  — #FEF2F2 底 / #B91C1C 字
● 在途      — #EFF6FF 底 / #1D4ED8 字
```

**规则:** 圆点 + 文字，绝不只用颜色区分（色盲可用）

### 5.3 数据表格

| 规则 | 说明 |
|------|------|
| 无线条 | 无竖线 · 仅表头下 1px 横线 · 行间细线 `#F0F3F9` |
| 表头 | 11px 大写 `#98A4B8` · 字距 0.1em |
| 数字列 | 右对齐 · `tabular-nums` |
| hover | 行 hover 浅蓝底 |
| 无斑马纹 | 斑马纹 + 边框 + hover 变色 = 三套视觉语言打架 |

### 5.4 KPI 指标卡片

**三要素规则（不要放图标、进度条、多种颜色堆叠）：**

```
标签 11px 灰        本月账实相符率
数字 40px 800       99.6%
脚注一行说清对比     ▲ 0.4pt  目标 99.5%
```

### 5.5 阴影（仅三档）

| 级别 | 值 | 用途 |
|------|-----|------|
| **sh-1** | `0 1px 2px rgba(10,15,30,.05)` | 卡片默认 |
| **sh-2** | `0 2px 4px rgba(10,15,30,.04), 0 12px 28px -12px rgba(...)` | 卡片 hover |
| **sh-3** | `0 24px 60px -24px rgba(10,15,30,.22)` | 弹窗/下拉 |

卡片默认只有 1px 描边 + sh-1，悬浮时提升到 sh-2。

## 6. 动效

只做位移和透明度，别做弹跳。动效的作用是交代层级与因果，不是炫技。

**统一缓动曲线:** `cubic-bezier(.2, .7, .2, 1)`

| 场景 | 时长 | 做法 |
|------|------|------|
| hover / 焦点 | 120–180ms | 背景或描边变化，位移 ≤ 2px |
| 弹窗 / 抽屉 | 240ms | 透明度 + 位移，不加缩放 |
| 数字变化 | 320ms | 滚动计数，不做弹跳 |
| 卡片入场 | 600ms | 上移 16px + 淡入，列表按 60ms 错峰 |

**无障碍:** 必须遵守 `prefers-reduced-motion`，用户开启减弱动效时所有位移与过渡直接取消。

## 7. 图形、图标与页面骨架

### 7.1 图形语言

| 类型 | 规则 | 说明 |
|------|------|------|
| **抽象几何** | 网格、信号波形、等距方块、批次流向 | 呼应芯片与测试的物理形态 |
| **渐变光斑** | 仅深色区块，低透明度、大半径模糊 | 制造空间感 |
| **线性图标** | 24px 网格 · 1.75px 描边 · 圆头端点（Lucide 风格） | 禁止混用填充与线性两套 |

### 7.2 页面骨架

- **工作台:** 顶部状态条 → KPI 三卡 → 主图表 → 待办列表，最多四段
- **列表页:** 筛选条 → 表格 → 分页，筛选条固定顶部
- **详情页:** 两侧栏布局，右侧可选展开 CollabChat 面板

### 7.3 深浅色策略

- **默认浅色**，深色只用于 hero 与强调段，**不做全站深色模式**（避免长表格在深底下疲劳）
- 深色底: `#0A0F1E`，主色提亮 15%（`#6366F1`），文字用 `#DCE3F0` 而非纯白

## 8. 移动端 H5

车间场景核心目标：**一只手、戴手套、光线差 → 3 秒内完成一次扫码确认**。

| 规则 | 说明 |
|------|------|
| **48px 触控高度** | 主操作按钮最小 48px，间距 ≥ 12px，防误触 |
| **对比度 ≥ 7:1** | 正文加深到近黑，不用浅灰字 |
| **单手可达区** | 主操作固定在屏幕下 1/3，顶部只放标题与返回 |
| **一屏一确认** | 扫码结果必须在一屏内看清"料号 / 批次 / 数量"三个字段 |

## 9. DO / DON'T 对照表

| DO ✅ | DON'T ❌ |
|------|---------|
| 大标题 800 字重 + 负字距，正文 15.5px 放松行高 | 标题加阴影或描边 |
| 卡片 16px 圆角 + 1px 描边 | 卡片套卡片 |
| 一屏只用一个强调色 | 一个页面出现四五种蓝 |
| 表格去掉竖线，靠留白分隔 | 表格加斑马纹再加边框再加 hover 变色 |
| 数字右对齐并等宽 | 图标一半线性一半实心 |
| 按钮用统一 10px 圆角 | 按钮用三种不同圆角 |
| 空状态：一句话说明为什么空 + 一个明确动作 + 线性小图 | "暂无数据"四个字挂在屏幕中央 |

## 10. 验收清单

**上线前置条件，逐项打勾：**

| # | 维度 | 验收标准 |
|---|------|---------|
| 1 | 色彩 | 全站主色仅 1 个，语义色仅 4 个；无纯黑纯灰；正文对比度 ≥ 4.5:1 |
| 2 | 字体 | 字号不超过 6 档；标题字重统一 800；所有数字等宽右对齐 |
| 3 | 间距 | 随机抽查 10 处间距，全部为 4 的倍数 |
| 4 | 圆角 | 全站仅出现 8 / 12 / 16 / 22 / 999 五种值 |
| 5 | 阴影 | 仅三档；卡片默认只有 1px 描边 + 极浅阴影 |
| 6 | 动效 | 时长取自 120/180/240/320/600；开启减弱动效后无位移 |
| 7 | 响应式 | 1440 / 1200 / 992 / 768 / 480 五个断点无横向滚动、无文字截断 |
| 8 | 无障碍 | 键盘可完整操作；焦点环可见；状态不单靠颜色传达 |
| 9 | 一致性 | 同类组件在不同页面视觉完全一致（对照组件库截图逐项核对） |

## 11. CSS 变量参考

```css
:root {
  /* 品牌色 */
  --brand:        #4F46E5;
  --brand-2:      #7C3AED;
  --brand-soft:   #EEF0FF;
  --cyan:         #06B6D4;

  /* 中性色 */
  --ink:          #0A0F1E;
  --ink-2:        #1B2436;
  --body:         #3F4B60;
  --muted:        #6B7A90;
  --faint:        #98A4B8;
  --line:         #E7EBF3;
  --line-2:       #F0F3F9;
  --canvas:       #F6F8FC;
  --paper:        #FFFFFF;

  /* 语义色 */
  --ok:           #10B981;
  --warn:         #F59E0B;
  --danger:       #EF4444;
  --info:         #0EA5E9;

  /* 圆角 */
  --r-sm:         8px;
  --r-md:         12px;
  --r-lg:         16px;
  --r-xl:         22px;

  /* 阴影 */
  --sh-1: 0 1px 2px rgba(10,15,30,.05);
  --sh-2: 0 2px 4px rgba(10,15,30,.04), 0 12px 28px -12px rgba(10,15,30,.10);
  --sh-3: 0 24px 60px -24px rgba(10,15,30,.22);

  /* 动效 */
  --ease: cubic-bezier(.2, .7, .2, 1);
}
```

## 12. 交付物

| 角色 | 交付内容 |
|------|---------|
| **设计侧** | Figma 组件库（按钮/表格/卡片/表单/图表模板）、页面高保真、标注文件 |
| **开发侧** | CSS 变量表（`--color-*` / `--space-*` / `--radius-*`）、组件库 Storybook、暗色段样式 |
| **验收侧** | 第 10 节 9 条清单逐项打勾，作为上线前置条件 |

> **规范的价值不在于写得多全，而在于能不能被违反时立刻看出来。** 所以每一条都给了具体数值——"要现代一点"没法验收，"圆角只有 8/12/16/22"可以。
